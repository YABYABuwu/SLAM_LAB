# กริดกำแพงสี่ด้าน

กริดเดินใช้ `exploration.step_m` เป็นขนาดช่อง (ปัจจุบัน 0.60 เมตร) ศูนย์กลางช่อง `(0,0)` อยู่ที่ pose เริ่ม DFS และแกนกริดหมุนตาม yaw เริ่มต้น แต่ละช่องมีด้าน `x+`, `y-`, `x-`, `y+` และขอบระหว่างช่องใช้ข้อมูลเดียวกัน เช่น `x+` ของ `(0,0)` ตรงกับ `x-` ของ `(1,0)`

## การสร้างกำแพง

`CellWallGrid` อยู่ใน `src/slam.py` เพราะ occupancy ละเอียดเดิมเก็บเพียงจุดปลายรังสีและไม่มีข้อมูลว่าด้านใดของช่อง DFS มีกำแพง คลาสนี้รับ scan ที่ DFS ยืนยันแล้วจาก `SensorLogger`/`SlamWorker` เดิม ไม่มี subscription เพิ่ม

เมื่อ gimbal หันถึงเป้าหมาย, SDK action สำเร็จ และได้ ToF ใหม่ตรงทิศ ให้คำนวณระยะจุดชนจากศูนย์กลางช่อง รวมตำแหน่งหุ่นจริงและ offset ของ ToF แล้ววางกำแพงบนขอบกริดที่ใกล้ที่สุดตามแนวรังสี ขอบที่รังสีผ่านก่อนถึงกำแพงเป็น `open` ขอบที่ยังไม่ได้ตรวจเป็น `unknown` และข้อมูลล่าสุดอัปเดตขอบร่วมทั้งสองฝั่ง

ตัวอย่างช่อง 0.60 เมตร: ขอบอยู่ที่ระยะ 0.30, 0.90, 1.50 เมตรจากศูนย์กลาง ถ้าระยะจุดชนรวม offset เป็น 1.555 เมตร จะได้ทางเปิดสองขอบแรกและกำแพงที่ขอบ 1.50 เมตร การฉายมีเพดานจำนวนช่องตามขนาดแผนที่ละเอียด (สูงสุด 1000 ขอบต่อ ray) ถ้ารังสียาวเกินเพดานจะไม่สร้างกำแพงปลอมที่จุดตัด

นี่เป็นแบบจำลองทางเดินที่กำแพงจัดตามช่องขนาดคงที่ การปัดจุดชนลงขอบกริดไม่ยืนยันว่ากำแพงจริงเต็มทั้งขอบ โดยเฉพาะสิ่งของเฉียงหรือวัตถุที่อยู่กลางช่อง จึงเก็บระยะจริงเพื่อทดสอบพื้นที่สำหรับตัวหุ่นแยกจากสถานะขอบ

## การเดินและการถอยกลับ

สแกนครบสี่ทิศจากจุดปัจจุบันก่อนเลือกทาง DFS อ่านสถานะขอบจากกริด และข้ามได้เมื่อขอบเป็น `open` พร้อม `clearance_ok` จากการสแกนที่จุดปัจจุบัน ขอบเปิดที่อนุมานจากช่องข้างเคียงยังไม่มีสิทธิ์ให้เดินจนกว่าจะสแกนใหม่ที่จุดนั้น

ระยะ ToF ต้องพอสำหรับ `step_m - pose_along - sensor_offset + robot_radius_m + clearance_margin_m` โดย `pose_along` ชดเชยตำแหน่งจริงที่คลาดจากศูนย์กลางช่อง ก่อนออกคำสั่ง chassis จะสแกนทิศที่เลือกอีกครั้ง กฎนี้ใช้กับการย้อน stack ด้วย ส่วนข้อมูล pose/status เก่าหรือสัญญาณผิดปกติยังหยุดการเคลื่อนที่ตามเดิม

## Dashboard, export และ review

- มุมมองปกติแสดงขอบกำแพงสีส้ม ทางเปิดสีเขียว และขอบยังไม่รู้เป็นเส้นประเทา พร้อมพิกัดช่องและสถานะสี่ด้าน แกนจอ +X ขึ้น / +Y ขวา ส่วนแกนช่องอ้างอิง `base_pose`
- ช่องเลือก “แสดง occupancy ละเอียด” เปิดกริดเดิมร่วมกับกำแพง จึงตรวจเทียบข้อมูลได้
- `robomaster-occupancy-grid` ยังคง version 1 และลำดับ `data` เดิม เพิ่ม `exploration.cell_grid` version 1 ประกอบด้วย `cell_size_m`, `base_pose`, `current`, `cells[].index`, `cells[].sides` ซึ่งแต่ละด้านมี `state` และเมื่อวัดที่ช่องนั้นแล้วจะมี `range_mm`, `required_range_mm`, `clearance_ok`, `observed_at`
- Map JSON/ROS ZIP (`slam.json`) เก็บกริดกำแพงด้วย ส่วน ROS PGM คงเป็น occupancy ละเอียด การ import ตรวจ schema และขอบร่วมที่ขัดแย้งกันก่อนแก้ map; ไฟล์เดิมที่ไม่มี `cell_grid` ยังเปิดได้
- การเปิด map เก่าแสดงกริดที่บันทึกไว้ การเริ่ม DFS รอบใหม่สร้างกริดช่องจาก pose เริ่มใหม่และสแกนใหม่ ไม่ใช้ clearance เก่าอนุญาตให้เดิน
- `run_summary.json.exploration` เก็บ snapshot สุดท้ายแม้รันล้มเหลว หน้า review แสดงตารางกำแพงแยกจากตัวเลื่อนเวลา ยังไม่มีประวัติกริดทุกช่วงเวลา รันเก่าแสดงว่าไม่มีข้อมูลกริด
